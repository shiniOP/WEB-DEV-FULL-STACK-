DOM (Document Object Model)
The DOM is a programming interface for HTML and XML documents. It represents the structure of a document and allows programs to modify its content and presentation in js

events -> it is an action that occurs in the browser, such as a user clicking a button or a page loading. We can use events to trigger functions and change the behavior of a web page
event listeners -> it is a function that waits for a specific event to occur and then executes a callback function in response to that event. We can use event listeners to add interactivity to our web pages
event action -> it is an action that occurs in response to an event, such as changing the text of a button when it is clicked or displaying a message when a form is submitted. We can use event actions to provide feedback to users and improve the user experience of our web pages
bubbling -> it is a way for events to propagate up the DOM tree, allowing parent elements to respond to events that occur on their child elements. We can use bubbling to create more efficient event handling and reduce the number of event listeners needed on a page

js is a single threaded language -> it means that it can only execute one task at a time. However, we can use asynchronous programming to allow js to perform multiple tasks concurrently, such as making network requests or reading files from disk, without blocking the main thread of execution. This allows us to create more responsive and efficient web applications.
web apis -> it is a set of APIs that are provided by the browser to allow js to interact with the web page and perform tasks such as making network requests, manipulating the DOM, and storing data in the browser. We can use web APIs to create more dynamic and interactive web applications.
apis -> it is a set of functions and protocols that allow different software applications to communicate with each other. We can use APIs to access data and services from other applications and integrate them into our own web applications.

dom api -> it is a set of methods and properties that allow js to interact with the DOM and manipulate the content and structure of a web page. We can use the DOM API to create dynamic and interactive web applications that respond to user input and events.
fetch api -> it is a web API that allows js to make network requests and retrieve data from a server. We can use the Fetch API to create dynamic and interactive web applications that can retrieve and display data from external sources, such as APIs or databases.
callback() -> it is a function that is passed as an argument to another function and is executed after the first function has completed its task. We can use callbacks to handle asynchronous operations and ensure that our code executes in the correct order.
callback hell -> it is a situation where multiple nested callbacks are used to handle asynchronous operations, resulting in code that is difficult to read and maintain. We can avoid callback hell by using promises or async/await syntax to handle asynchronous operations in a more structured and readable way.

promise -> it is an object that represents the eventual completion (or failure) of an asynchronous operation and its resulting value. We can use promises to handle asynchronous operations in a more structured and readable way, avoiding callback hell and improving the maintainability of our code.
fulfilled -> it is a state of a promise that indicates that the asynchronous operation has completed successfully and has returned a value. We can use the .then() method to handle fulfilled promises and access their resulting values.
rejected -> it is a state of a promise that indicates that the asynchronous operation has failed and has returned an error. We can use the .catch() method to handle rejected promises and access their error messages.
we read promises only when the request is fulfilled or rejected, we can use the .then() and .catch() methods to handle the resulting values or errors, respectively. This allows us to write more readable and maintainable code that handles asynchronous operations in a structured way.
json -> it is a lightweight data interchange format that is easy for humans to read and write, and easy for machines to parse and generate. We can use JSON to exchange data between web applications and servers, and to store data in a structured format that can be easily accessed and manipulated in js.
promise chaining -> it is a technique that allows us to chain multiple promises together, so that the output of one promise can be used as the input for the next promise. We can use promise chaining to create more complex asynchronous workflows and handle multiple asynchronous operations in a structured and readable way.
json vs js object -> json is a string representation of a js object, while a js object is a data structure that can hold multiple values and properties. We can use JSON to exchange data between web applications and servers, while we can use js objects to store and manipulate data within our own applications.

response -> it is the data that is returned from a server in response to a request made by a client. We can use the response data to update the content and behavior of our web applications, and to provide feedback to users about the status of their requests.
async/await -> it is a syntax that allows us to write asynchronous code in a more synchronous and readable way, using the async keyword to define an asynchronous function and the await keyword to pause the execution of the function until a promise is fulfilled or rejected. We can use async/await to handle asynchronous operations in a more structured and readable way, avoiding callback hell and improving the maintainability of our code.
